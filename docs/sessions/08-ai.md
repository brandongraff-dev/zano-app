## Files

- `backend/supabase/functions/meal-vision/index.ts` — accepts a private-bucket photo path, calls a
  vision LLM with a strict-JSON-output prompt matching §9.5's exact shape
  (`{items:[{name, grams_protein_est, confidence}], total_protein, notes}`), stores into `meals`.
- `backend/supabase/functions/weekly-recap/index.ts` — meant to run from pg_cron Sunday 6pm,
  aggregates a week's `goal_events`, calls an LLM with §9.6's strict template (max 60 words, coach
  voice, one win, one suggestion, no shame), stores into `recaps`.
- `Core/Sources/Core/Verification/QuickRepeatSuggester.swift` — on-device surfacing logic for
  "Your usual chicken bowl (48g)?" (§5.19), added in the follow-up batch.

## Known issues / what's NOT done

- Both Edge Functions read the LLM API key from `Deno.env` only (never hardcoded) but reference a
  placeholder env var name — no real provider/model has been chosen yet, deliberately (this wasn't
  specified in the spec beyond "a vision LLM API").
- **The weekly-recap function is not actually scheduled** — the pg_cron registration is Session
  12's `0004_ml_feature_job.sql`'s job, not this session's; confirm both land together.
- Recap card rendering as a 9:16 shareable image is `Core/Sources/Core/UI/Components/ShareCard.swift`
  (Session 5) + `App/ZANO/Features/Share/WeeklyRecapShareView.swift` (Session 11's cluster) —
  cross-reference those docs, not duplicated here.
- `QuickRepeatSuggester`'s output isn't wired into `FuelView.swift` yet — noted as a follow-up by
  the agent that built it rather than risking an edit collision on an in-flight file.
